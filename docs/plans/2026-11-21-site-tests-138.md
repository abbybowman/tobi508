## W4: the script that draws nothing

**Cause (verified, 2026-11-21).** `script.crazyegg.com`'s Cloudflare
refuses the `HeadlessChrome` user agent: curl with that one header gets
**HTTP 403, `text/html`, "Attention Required! | Cloudflare … Sorry, you
have been blocked"**; with a `Chrome/…` agent, or none, 200
`text/javascript`. Referer and Sec-Fetch headers make no difference.
Chromium's ORB then refuses an HTML answer to a cross-site script request.
The tool's HAR entry: status -1, no headers, `_failureText:
net::ERR_BLOCKED_BY_ORB`, request `User-Agent: … HeadlessChrome/157…`
(Chromium drops the response before the HAR sees it). Not the egress proxy
or the container's: plain Playwright Chromium through the container's proxy
gets the same, and the svs and science.data scripts load. A headed Chrome
(a tester's) is not refused. The tool runs headless wherever it is hosted.

science.data's results are in the served document (Drupal views rows,
server-drawn), and the tag is named with `async`: it draws nothing.

## Freeze: reruns serve other pages from the freeze

Found by reading `frozen.obtain`: any address the freeze holds is served
from it in both modes, before the mode is looked at, so the caller's other
pages already come from the freeze in `tested_frozen` too. What loads live
there is only what 19.A loads itself: aliases, suggested pages and the
search; in replay those are refused (W7, W8, W4). The step is therefore: a
copy of each round's freeze with the pages 19.A loads itself added
(recorded once, under the same rules, new hashes recorded, the original
kept, as #134 did for round 3), so a replay rerun decides 19.A on
everything but the live search. No spec change.
